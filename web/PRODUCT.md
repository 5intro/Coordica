# 已确认产品事实

Coordica 是单项目中心协调分布式 Runner 的开发工作台。首页服务于日常推进工作（Operate），所有状态来自现有 Snapshot，不产生新授权或状态转换。

首页页内包含项目名、已保存目标、按已集成或验证完成任务计算的进度（取消不计入）、暂停状态及提交需求入口。人工待办仅呈现实际需要批准、决策或停止核验的记录，无事项时整区隐藏。需求、任务、审查、阻断四池每池最多展示五条活动事项、活动总数及完整池入口。需求无独立状态字段，活动需求定义为尚无关联任务或仍有关联非终态任务。

审查池复用 candidates 的真实 ID 和固定 commit；prechecking 尚未进入 Agent 审查，首页活动审查只列 reviewing 与 ready_to_land；完整审查页面保留预检查与历史筛选。历史失败和已合并候选不进入活动列表，不虚构 ReviewTask。

主机动态按 nodes 与 runs.node_id 分组，只展示实际活动 Run（含未确认静止的失联 Run）。能力探测不是运行实例或认证证明；最后上报时间不是永久在线证据。未知主机 ID 的活动 Run 仍须可见。

现有初始化、规划、自动化、审计、恢复与设置保持可发现入口；测试中心已接入工作台。功能包括完成态、固定版本就绪证据、失败修复关联、准备停止和恢复；黄金旅程及授权、取消、恢复、咨询丢ACK断言必须保留。视觉修订不修改API或后台。


## 已确认视觉反馈

用户访谈已完成。用户明确反对工作台普遍使用灰绿，不再重新访谈。本轮受托设计采用纸白工作面、浅冷背景、深墨蓝Dock与蓝色选择/操作；成功绿仅传达真实成功或可用性，能力探测不能冒充运行或认证。使用者在笔记本上日夜持续查看项目进展、需求、阻断与实际运行，需要紧凑清楚、可读的工作列表。

保持四池2×2、实际主机实例和底部Dock；所有既有入口、权限、取消及恢复行为保留。移动端结构换列，长目标与技术证据按需展开。此任务不新增产品目标或执行权限。
