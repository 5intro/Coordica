# 已确认产品事实

Coordica 是单项目中心协调分布式 Runner 的开发工作台。首页服务于日常推进工作（Operate），所有状态来自现有 Snapshot，不产生新授权或状态转换。

人工验收在测试中心的需求验收详情中完成。Owner 逐项确认人工条款并说明验证情况，签收固定提交和准确覆盖摘要；
自动条款缺少当前证据时不能签收。签收与测试通过、代码集成分开记录，支持撤销并按需查看最近十次历史。
需求撤回、条款或证据变化后，原签收不再表示当前版本已验收；仍可撤销旧声明。
结果未知的提交按当前凭据会话保留原始版本、说明、人工条款和请求身份，换页或刷新覆盖后不能静默换成新版本签收。

首页页内包含项目名、已保存目标、按已集成或验证完成任务计算的进度（取消不计入）、暂停状态及提交需求入口。人工待办仅呈现实际需要批准、决策或停止核验的记录，无事项时整区隐藏。需求、任务、审查、阻断四池每池以默认约两到三张卡片的高度展示活动事项，完整活动列表可在池内滚动、活动总数；池名位于凹槽上方并作为完整池入口，不重复显示“查看全部”。需求具有内容修订号和撤回状态；活动需求为尚无当前修订的关联任务，或当前修订仍有关联非终态任务；撤回保留在历史。

审查池复用 candidates 的真实 ID 和固定 commit；prechecking 尚未进入 Agent 审查，首页活动审查只列 reviewing 与 ready_to_land；完整审查页面保留预检查与历史筛选。历史失败和已合并候选不进入活动列表，不虚构 ReviewTask。

主机动态按 nodes 与 runs.node_id 分组，只展示实际活动 Run（含未确认静止的失联 Run）。能力探测不是运行实例或认证证明；最后上报时间不是永久在线证据。未知主机 ID 的活动 Run 仍须可见。

现有初始化、规划、自动化、审计、恢复与设置保持可发现入口；测试中心已接入工作台。功能包括完成态、固定版本就绪证据、失败修复关联、准备停止和恢复；黄金旅程及授权、取消、恢复、咨询丢ACK断言必须保留。视觉修订不修改API或后台。


## 项目准备

项目准备沿用原初始化入口与同一轮中心记录；普通聊天中的交互层和 Web 可继续同一轮访谈。
已确认约定、待确认草案、原始反馈、源码证据和 Owner 检查政策分别呈现；日常隐藏内部标识，完整证据按需展开。
回答和检查政策草稿固定打开时的版本；新版本到来后需重新核对，不能把旧输入静默附到新版本。
未收到回答回执时，重试沿用原文、来源、问题版本和请求身份。确认项目约定不会批准开发目标或恢复调度。
草稿及待确认请求保存在当前凭据会话的内存中，按项目隔离，切换页面后可恢复；断开工作台或重新载入浏览器后不承诺保留。
仅选中问题、尚未输入文字时也保留所选版本。回答及政策回执必须完整；结果未知时冻结原始内容、版本与请求身份，供同身份重试，不能借刷新静默改写。
无效 JSON 或不完整的初始化回执仍视为结果未知，不能清空原始回答或生成新的提交身份。

## 已确认视觉事实（H）

用户明确指定 macOS 组件作为本次替换方向。浏览器工作应用保留四池 2×2、真实主机及八入口底部 Dock；各尺寸均保留八入口 Dock，去除重复工作池切换。没有假窗口按钮、桌面或全局侧栏。页首仅品牌与搜索，完整导航由底部 Dock 提供。当前已批准米白背景、原衬线字标、玻璃卡片和轻微凹槽；具体规范见 DESIGN.md。

日常列表优先任务、需求、套件、主机名称；缺失关联明确标为未命名或历史记录。内部 UID、完整指纹、授权及进程标识保存在默认关闭的技术详情中。原文、助手摘要及来源分别可查；接口参数、深链接和真实证据不变。

测试中心分为套件、执行记录、覆盖与就绪。选择套件后展开执行表单；报告按需展开，testing?run 深链接进入执行记录并定位。固定提交、有限预算、重试 0–2、平台限制和暂停排队保持原语义。就绪按当前完整提交查询，不以历史成功、缺少套件、取消或平台不符推断通过。

设置使用成组行和真实控件，技术命令、路径及诊断渐进展开。保留初始化、Leader、自动化、审计、恢复及配对入口，不新增没有 API 的配置能力。


## 已批准样稿接入

首页采用样稿密度：限定池高并在内部滚动、点池名进入完整页面，人工待办首项加总数，主机仅呈现真实当前运行；其他记录有完整入口。首页点击事项先查看轻量详情，原文、动态与关联按分段查看；批准、撤销、停止证明和范围等操作继续由原业务页面及同一 ApiClient/useAction 执行。新需求使用共享表单，失败保留输入，中心接受后才显示成功。

亮柠檬绿仅保留已批准的 Dock 当前底座与人工待办强调，不增加用量。凹槽浅米灰，左上内阴影接近右下反光的轻度。玻璃折射要求连续、边缘更强且不发生取样折返条纹；遵从减少动态效果，其他浏览器保留磨砂回退。


行高与页首：四池按两组行组织，每行底部有低干扰拖拽分隔条，同一行的两个池同步调整，卡片独立滚动不带动页面。支持方向键、Home 恢复默认、End 最大、双击复位；高度仅存本机浏览器，与后台策略无关。页首只保留 Coordica 字标和搜索，移除“协作工作台”副标题。


池页页首：删除重复的需求／任务／审查／阻断切换条；“全部／活动／历史”位于各池标题同一行，新增操作留在该行右侧，窄屏必要时只将操作换行。底部 Dock 在小屏保持全部八个去向，避免删除重复导航后丢失入口。

## 池详情与 Agent 配置

四个完整池页采用左侧单列事项、右侧内联详情；列表与详情可分别滚动，窄屏顺序排列。首页仍保留四池两列两行与轻量详情面板。阻断列表按选择呈现证据和操作，停止证明、版本和候选规则继续生效。

Agent 管理按主机、Agent 工具、当前任务三列关联；点击工具在右侧编辑。只展示各 Runner 实际探测到已安装的 harness，未安装的注册模板不占位；已安装但版本探测失败仍显示异常，旧节点成功可用报告保持兼容。能力报告与实际运行分别呈现，工具不再报告时仍保留在途/未确认静止的失联运行，来源主机缺失的运行仍可查。无已装工具的主机保留空状态。主机设置与协议诊断折叠。

Owner 可以按主机和工具设置新 Run 的模型及思考强度；调用既有版本化节点配置用例，保持其他工具权限。只有工具结构化接口报告的值才能保存；界面不提供手输模型或通用强度名单。Codex 开放工具实际报告的全部模型，未选择时沿用 gpt-6.1-sol；不得覆盖用户选择或静默回退。未知或失效的参数不获派新任务。Run 固定执行参数，改配置不影响运行中的任务。保存失败保留草稿；节点版本改变必须重新核对。此项是用户追加授权的后端扩展，不代表扩大正在暂停的自举目标或运行权限。

发现方式：Codex app-server model/list；Claude Code 控制协议初始化模型目录；ACP session/new 返回的 model/thought_level 配置；pi RPC 模型和当前模型的强度查询。ACP/pi 对其他模型未报告的强度保持未知；执行会话必须确认所选参数，不能默认降档。工具升级后采用新报告的值，不把 max 当作某个工具的永久上限。发现结果仅是配置能力，不是账号、执行或跨平台认证。

## 需求生命周期

需求详情保留左侧单列、右侧详情布局，加入修订、撤回与版本历史。修订表单固定打开时的记录版本；失败保留输入，读取影响范围失败时不能提交。内容修订与元数据版本独立，历史每次读取二十项。当前内容和最初聊天原文分别展示，内部标识继续折叠。

正式变更由 Owner 提交。新需求由 Leader 判断合并未派任务或创建关联后续任务；修订冻结受影响未完成工作，确认旧 Run 停止后重排，旧 Run 和旧规划结果不能推进新版本。共享任务保留其他有效需求，撤回专属任务但不抹掉历史；已集成代码生成补偿任务走原门禁。重排保持消耗、重试、修复及独立人工阻断。暂停或自动化关闭时只排队；阻断的变更可由 Owner 明确重评，不改变开关。有限 MCP 保留建议权限，不获得正式修改决策权限。

## GitHub PR 与本地 Git

代码集成设置保存发布模式与明确的必需 CI 名称，只有暂停且执行、候选和发布意图均安全结束时才能切换。没有凭据输入框，切换不恢复项目或改变代码基线授权。审查池继续使用真实候选，GitHub 区显示原 PR 链接、CI、评审、同步时间与失败原因；修复更新原 PR，不新增第二个批准按钮。旧提交证据标为历史。暂停时仅刷新已有 PR 的只读状态。
